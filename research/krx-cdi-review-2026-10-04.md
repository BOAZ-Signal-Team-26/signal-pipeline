## ERD·CDI 저장 계약

`docs/schema.dbml`과 `docs/data-model.md`·`docs/scoring-and-population.md`를 비교했다.

| 확인 항목 | 현재 계약 | 판정 |
|---|---|---|
| 원값·결측 | `score.raw_score`, `result_status`, `reason_code`, `normalized_score`, `normalization_status`를 분리. OK가 아니면 원값 NULL | 0점과 계산 불가를 구별할 수 있음 |
| 근거 위치 | `score_payload`에 `section_id`, Unicode code point 기준 `[char_start,char_end)`; `section`은 원본 파일·파서 버전·본문 해시와 연결 | 양성/음성 판정의 위치를 기록 가능. JSON 안 참조와 좌표 범위는 적재 검증으로 강제해야 함 |
| 실행별 모집단 | `population_snapshot`에 run·지표·층·회원 수·manifest 경로/해시, `pipeline_run`에 입력·선택 manifest 경로/해시 | 당시 구성원을 파일로 재현 가능. 파일 영구보존·해시 검증은 운영 필수 |
| 위험등급 층 | `fund_group` 대표 등급과 출처 문서, 실행 입력 manifest에 상품·등급 스냅숏 | 당시 등급을 고정할 자리는 있음. 클래스 간 등급 충돌 처리와 대표 등급 칼럼은 아직 결정 대기 |
| 공식 CDI | `metric_definition`의 불변 버전과 승인 상태, 실행 설정·가중치 기록 | 0~1 변환법, 고정 기준집단, 최종 가중치가 승인 전이므로 **공식 점수 확정 불가** |

구조는 요구한 데이터를 담을 수 있다. 다만 `score_payload`와 여러 manifest가 파일/JSON 계약이어서 DBML의 FK만으로 근거 위치·회원 목록의 무결성이 완결되지는 않는다. 점수 게시 전에는 (1) 모든 근거 `section_id`가 SCORE 입력 manifest의 파서 버전과 일치하는지, (2) 좌표가 해당 canonical text 길이 안인지, (3) 모집단의 고유 `fund_key` 수가 manifest와 `population_snapshot` 집계와 일치하는지를 적재 검증으로 확인해야 한다. 이는 현재 문서에도 적재 검증으로 예정돼 있으나 실제 데이터/파이프라인 실행 결과는 없다.
