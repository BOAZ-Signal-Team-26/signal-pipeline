# 점수 저장과 비교 모집단

점수 저장 단위, 결측 상태, 비교 모집단, 대표본 선택, 판매 중 확인, 알려진 분석 위험.

## 상태

| 항목 | 값 |
|---|---|
| 판 | v2 저장 계약 (2026-09-23), v2.1 실행 분리 반영 |
| 유지하는 팀 결정 | 펀드 단위 통계, run_id 통일, 비교 모집단 별도 표 (09-20). 채점 단위는 10-02 변수표로 문서 단위로 바뀜(「저장 단위와 계산 단위」) |
| 지표 구성 기준 | Notion 「CDI 4축 변수표 (10/2)」(데이터 사이언스(다빈) 작성). 이 문서의 지표 목록·계산식은 변수표를 따름 |
| 승인 | 파트 B 가중치(파일럿 전 축 1·2)·스케일링 방법·기준집단은 다빈 제안·팀 승인 전 |
| 칼럼 정본 | [DBML](schema.dbml), [스키마 명세](schema-catalog.md) |

## 저장 단위와 계산 단위

| 대상 | 단위 | 저장/계산 |
|---|---|---|
| 축 1·2 지표 원값(파일럿 전 파트 B 입력) | 실행의 대표 파일/문서 | DOCUMENT 대상의 score. 문서 전체에서 직접 계산 |
| 축값·파트 B 합산 | 실행의 대표 파일/문서 | DOCUMENT/FUND 대상의 score와 score_dependency. 공식은 CDI 산식 계약 |
| 파트 A 항목 판정(축 4)·작성기준 항목 점검(3-1a, 3-1b-① 위치 준수, 간이 3-1) | 문서 × 항목 | DOCUMENT 대상의 score. 항목마다 metric_key 하나([데이터 테이블·ERD 설계](data-model.md) 「두 파트 출력의 저장 계약」) |
| 고칠 곳 위치·근거 위치 | 절 + 문자 범위 | 점수가 아니라 근거 위치. 위치 형식은 결정 요청 B11 |
| 요약-본문 중복도 | 같은 문서의 구간쌍 또는 다른 파일쌍 | Phase 2(10-02 변수표). 도입 시 DOCUMENT_PAIR 대상의 score, member에 양쪽 파일/구간·역할 기록 |
| 통계 관측치 | 실행·기준일·고유 fund_key | 대표본 한 건의 값. 클래스별 반복 관측 금지 |

- 계산 단위: 문서 1건당 값 하나(10-02 변수표). 축 4와 작성기준 항목 점검만 항목별
  - 이전 원칙 「문서 집계 = f(절 점수)」는 쓰지 않음. ASL을 절별 평균으로 만들면 짧은 절이 과대 반영되고, 전문용어 밀도(단어 종류 비율)는 절 값의 합으로 만들 수 없음
  - 절 분할은 계속 필요: 작성기준 항목 점검은 부·절 제목과 순서를 보고, 설명 안 한 용어 비율은 맨 뒤 용어 목록 절을 찾아야 하고, 파트 A·B 출력은 위치(절 + 문자 범위)를 가리킴
  - 절 단위 점수(SECTION 대상의 score)는 필요할 때 따로 도입. 도입 시 짧은 절 처리 기준을 함께 정함
- 클래스의 점수 공유: 동일한 대표 문서/구간을 쓰는 경우에만
  - 모든 클래스 문서가 같다고 강제하지 않음
  - 다르면 대표본 정책으로 해소하거나 충돌 사유 기록
- 관측 단위 근거
  - 같은 펀드의 클래스 14~15건이 같은 PDF를 가리킴([금투협 중복 행 검증](records/phase1-erd/kofia-rows-and-etf-rule.md) 「검증 1: 금투협 중복 행」)
  - 클래스 단위로 넣으면 같은 CDI 값이 반복 관측치로 들어가는 의사반복(pseudo-replication) 발생
  - 절을 그대로 회귀에 넣으면 같은 문서의 절들이 문서 단위로 군집되어 표준오차 과소추정. 회귀 입력은 문서·펀드 집계값, 필요하면 문서 클러스터 강건 표준오차
- 조회 화면: 클래스는 투자자가 실제로 매수하는 단위라 클래스별로 노출
  - 이는 같은 점수를 클래스마다 조인해서 보여주는 것. 클래스마다 별도 관측치를 만드는 것 아님

## CDI와 고지 충실도

- 두 파트 출력: 09-29 팀 논의 결론, 9차 미팅(09-30) 확정
  - 문서 1건의 CDI 결과를 파트 A와 파트 B 두 부분으로 나눠 냄. 두 파트를 한 숫자로 합산하지 않음
  - 파트 A = 축 4 고지 충실도. 금융소비자보호법(금소법) 19조 항목별 「있음/없음/판정 불가」와 감점 표현 후보, 그 위치(절·문자 범위)
  - 파트 B = 읽기 난이도 점수. 같은 상품군 × 위험등급 층 안 백분위와 고칠 곳의 위치
    - 파일럿 전: 축 1 언어 복잡도·축 2 용어 부담을 합침. 축 3 구조 접근성은 이 버전에 없는 축으로 표시(10-04)
    - 파일럿 뒤: 3-2·3-3이 준비되면 축 3을 넣은 새 버전
  - 나누는 이유: 두 부분은 서로 다른 것을 잼. 한 점수로 더하면 「쉽게 썼지만 고지가 빠진 문서」처럼 가장 위험한 경우가 합산값에 가려짐
  - 출력 문구는 확인 가능한 사실로 씀. 「제재 가능성」 대신 「19조 N번 항목을 문서에서 찾지 못함」
- 지표 구성 (10-02 변수표)

| 축 | 지표 | 계산 | 보는 범위 | 출력 위치 | 상태 |
|---|---|---|---|---|---|
| 1 언어 복잡도 | 평균 문장 길이(ASL) | 어절 수 ÷ 문장 수 | 투자설명서 본문, 표 제외 | 파트 B | 확정 |
| 2 용어 부담 | 2-1 전문용어 밀도 | 어려운 단어 종류 ÷ 전체 단어 종류 | 투자설명서 본문, 표 포함 | 파트 B | 확정(형태소 분석기 시험 뒤) |
| 2 용어 부담 | 2-2 설명 안 한 비율 | 설명 없이 나온 어려운 단어 ÷ 어려운 단어 전체 | 본문(표 포함) + 맨 뒤 용어 목록 | 파트 B | 확정 |
| 3 구조 접근성 | 3-1a 항목 다 있나 | 있는 항목 ÷ 있어야 할 항목(작성기준 17~22장) | 부·절 제목 | 파트 A 옆 | 확정 |
| 3 구조 접근성 | 3-1b-① 위치 준수 | 정해진 자리에 있나(투자설명서는 표지 다음 페이지 유의사항, 작성기준 17-1-6 하나) | 표지·부 제목 | 파트 A 옆 | 확정(10-04) |
| 3 구조 접근성 | 3-1b-② 순서 일치도 | 작성기준 조문 순서와 다른 항목 목록 | 부·절 제목 | 메모만(점수 아님) | 확정(10-04) |
| 3 구조 접근성 | 3-2 설명만 하고 안 쓰는 용어 | 본문에 2회 이하 나온 용어 비율 | 맨 뒤 용어 목록 + 본문 | 표시만 | 잠정, 파일럿 뒤 축 3 재도입 입력 후보 |

- 정정 전후 점수 차이
  - 분석 가능. 현재값과 역사값은 섞지 않음
  - 정정이 이해를 돕는다면 CDI가 낮아질 수 있다는 가설. 실제 방향·크기는 측정 전 단정하지 않음

| result_status | raw_score | reason_code | 의미 |

| PENDING | NULL | 필수 | 계획됐으나 계산 전 |
| OK | 필수, 0도 유효 | NULL | 승인된 기준으로 계산 가능 |
| NOT_APPLICABLE | NULL | 필수 | 상품/서류/지표 적용 대상 아님 |
| UNDETERMINED | NULL | 필수 | 분모 0, 정의 미승인, 구조 부족, 판정 불가 |

- 계획 슬롯: target×metric×assessor 슬롯을 실행 입력 manifest와 PENDING 행으로 기록
  - 행 부재는 계획 외. 실패로 집계하지 않음
  - 완료 실행에 PENDING이 남으면 SUCCEEDED로 닫지 않음
- 비율 지표 OK: numerator/denominator와 양의 분모 필수. 산식·허용 범위 검증
  - 모든 원자값이 단순 비율은 아님. 분자/분모를 억지로 채우지 않음
- 축 안 결측: 축을 이루는 지표가 하나라도 OK가 아니면 그 축은 UNDETERMINED, 파트 B 합산도 UNDETERMINED
  - 남은 지표 하나로 축 값을 만들지 않음. 대체값을 넣지 않음
  - 예: 문서에 어려운 단어가 하나도 잡히지 않아 2-2의 분모가 0이면 축 2와 파트 B는 판정 불가

## 고지 항목 판정

- 저장 계약은 항목별 score 행 기준으로 바뀜([데이터 테이블·ERD 설계](data-model.md) 「두 파트 출력의 저장 계약」 참조). 아래 items 배열 구조와 member_id 근거 형식은 결정 요청 B11 결정 뒤 정리
- 항목 판정 4종: MET / UNMET / NOT_APPLICABLE / UNDETERMINED
  - 파트 A 출력 문구와의 대응: MET = 있음, UNMET = 없음, UNDETERMINED = 판정 불가. NOT_APPLICABLE은 적용 대상 아님으로 따로 표시
- payload v2 구조: `contract_version`, `unit`, `items[{item_key,status,reason,evidence[{member_id,block_id,char_start,char_end}]}]`, `applicable_count`, `assessed_count`, `coverage`, `preprocessing`
- block_id와 텍스트 구간은 멤버 파일의 structure_manifest/canonical text에 존재해야 함
- 문서 전체 부재 판정: 검사한 파일·범위·완전성도 기록
- 불명확한 법적 서류 대응과 후보 절은 확정하지 않음
- 문서 위치가 「제2부 10절(후보)」이면 후보로 보존
- 점검표에 빈 항목이 있다는 이유로 미충족 판정 금지
- 분모·미평가 공개 정책이 없으면 공식 최종 숫자는 비움
- payload v2는 3단계 입출력 Schema 설계에서 확정·수정 대상([3단계 입출력 Schema 설계 입력](io-schema.md) 「스키마에 먼저 들어간 모양」)

### 층 정의와 최소 표본

- 확정 기준(8차 미팅 기준을 10-04 PM 확정): 상품군 × 위험등급, 고유 fund_key 30개 이상, 층 병합 없음
- 30 미만: 원점수가 있어도 백분위 비움
- fndTp/prdClsfCd: 확보하되 현재 층에 자동 추가하지 않음
- 판매사·연도·문서유형: 층에 추가하지 않음
- 적용값은 `minimum_member_count`에 고정
- 30의 성격: 중심극한정리 근사와 백분위가 극단값 영향을 덜 받는 관행적 최소치. 정규성·검정력 보장 아님
- 인접 위험등급 층 병합: 채택하지 않음

### 층화와 결측

- 위험등급은 DART 표지 외에 금투협 첨부에서도 관측됨. 대체 소스가 있어도 결측 선택 편향이 자동으로 사라지지 않음
- 제외 사유를 남기는 경우: NAME_ONLY/PENDING, 위험등급 미상, fund_key 미정, 판매 여부 미확인, 대표본 충돌
- 층 자체를 배정할 수 없는 행: 실행 전체 제외 목록에 기록. 알 수 없는 위험등급에 임의 값을 넣어 「층별 제외」를 만들지 않음
- 매칭 실패: 원인과 분포 보존. 실패했다는 사실만으로 MNAR 증명이나 통계적 보정 불가를 단정하지 않음
- `etf_confidence = PENDING`: 정규화 모집단에서 제외, 제외 건수를 층별 기록
  - 보류 행을 ETF 층·펀드 층 어느 쪽에 넣어도 비교 기준이 왜곡됨
  - 제외 건수를 기록해야 층이 비는 원인이 표본 부족인지 판정 보류인지 구분 가능

| observation_unit | 의미 | 적용 |
|---|---|---|
| fund_document | 펀드당 대표 문서 집계값 하나 | FUND 대상(대표 문서) 또는 펀드 연결이 검증된 DOCUMENT 대상 |
| fund_section | 같은 의미의 절/같은 산식에 대해 펀드당 값 하나 | CDI 산식 담당이 동등 절을 정의한 뒤 SECTION에 적용. 그 전에는 생성 금지 |

- 문서 정규화는 문서 집계 후 수행
- 문서 백분위는 DOCUMENT/FUND 대상의 `score.normalized_score`에 저장
- SECTION의 normalized_score는 동등 절 비교가 정의됐을 때만. 미정은 NULL
- 쌍 지표는 임의로 문서 모집단에 넣지 않음
- 원점수/회원 목록/선택한 section_ids와 동점 처리·방향·산식 버전 함께 보존

### 축간 변환

- 축간 변환과 최종 층내 백분위는 별도 단계
- 여러 기준집단이 필요하면 별도 metric_key/score 행을 만들고 score_dependency로 연결
- 한 점수 행에 모집단 ID 여러 개를 숨기지 않음
- 불변 manifest 보존 항목: 기준집단 입력 원값·회원·동점 처리·변환 파라미터·평가자 선택 정책
- 축간 변환의 기준집단과 층내 백분위의 비교 집단은 다름. 기준집단은 [0,1] 변환에 쓰는 고정 문서 묶음으로 run을 넘어 유지하고 manifest(내용 해시 포함)에 보존. `population_snapshot`은 run마다 만드는 층내 백분위 비교 집단
- 파트 B 집계 공식과 가중치(파일럿 전 축 1·2)는 다빈 제안·팀 승인 전 DRAFT

## 기준일과 대표본 선택

| 순서 | 규칙 |
|---|---|
| 1 | run.baseline_date와 입력 컷오프 고정. 과거 자료 재현이면 당시 이용 가능했던 문서만 후보 |
| 2 | 확인된 동일 계보에서는 기준일 이하의 최신 유효 문서 선택. 현재 is_current=true라는 이유로 기준일 뒤 정정본 선택 금지 |
| 3 | 같은 fund_key에서 투자설명서 대표 1건과 간이투자설명서 대표 1건을 따로 고름(10-04 PM 확정). 한 역할 안에 소스가 여러 개이면 소스 우선순위 적용. 우선순위는 CDI 산식 담당 인계에서 확정. 간이 대표는 입력 경로 결정(「미결」)에 따라 투자설명서 안 「요약 정보」 절이거나 금투협 별도 PDF |
| 4 | 날짜 동률·소스 충돌·금투협 계보 미확정은 임의 ID 순서로 최신본 결정 금지. 선택 불가면 AMBIGUOUS_DOCUMENT 사유로 비교 제외 |
| 5 | 선택한 document_id뿐 아니라 raw_object_id/sha256, section_ids, 선택 이유를 입력·모집단 manifest에 저장 |

- 문서가 2행이라고 펀드가 2개인 것 아님. 파일 해시가 다르다고 서로 다른 비교 관측치인 것도 아님
- 펀드당 대표본은 역할별 하나라는 분석 정책을 실제 선택 단계에서 구현
  - 파트 B·층내 백분위·통계 관측치는 투자설명서 대표로만 셈. 간이 대표는 간이 3-1 점검에만 씀
- 「문서 1건 = 펀드 1건」은 DB 관계에서 자동 성립하지 않음. 정정·소스·정식/간이 파일이 여러 개일 수 있음
- DART 본문 속 요약과 금투협 별도 간이 PDF는 파일 SHA-256만으로 중복 판단 불가. 전체 파일 교집합이 0이어도 같은 펀드의 비교 관측치가 두 개 생길 수 있음 → [2단계 데이터 파이프라인 Flow 설계 입력](pipeline-flow.md) 「먼저 측정할 것: 소스 간 중복률」

## 판매 중 확인

- `inception_date = setpDt`는 설정일. 판매개시일의 확인된 원천으로 취급하지 않음
- sale_start_date/sale_end_date는 확인된 값만

| 분류 | 조건/의미 | 사용 |
|---|---|---|
| CONFIRMED_ACTIVE | 기준일의 판매/상장 근거 확인 | 다른 자격도 충족하면 확인 범위에 포함 |
| CONFIRMED_INACTIVE | 유효한 종료/미판매 근거 확인 | 제외 |
| UNKNOWN | 시작/종료/당시 상태 근거 부족 | 후보 집계로 별도 보고. 판매 중 확정 분모에 넣지 않음 |

- 이 상태는 현재 상품의 영구 boolean이 아니라 실행 기준일별 판정. 입력 manifest에 판정·근거·관측일 기록
- 경계 규칙(제안): 시작 포함·종료 제외 `start <= baseline < end`
  - 원천이 마지막 판매일을 종료일로 주면 포함 경계를 명시적으로 변환
  - end=NULL은 「종료일 모름」. 독립적인 기준일 판매 근거가 없으면 판매 중의 증거 아님
- KRX: 그 기준일의 검증된 거래일 자료에 존재하는 ETF를 관측
  - 어제 있었고 오늘 안 보인다는 이유만으로 상장폐지 확정 금지
  - 휴장, API 실패, 응답 절단, 승인 문제를 먼저 배제하고 별도의 상장폐지 근거/정책 확인
  - 이름 매칭 실패 229건도 상장폐지 아님
- 산출 범위 표시: 「관측된 상품 후보 중 채점 가능 범위」와 「판매 중 확인 범위」 구분
  - 종료일 원천이 부족하므로 전수성을 이미 달성했다고 보고하지 않음

### 문서 1건 = 펀드 1건 논증 (09-14~20 기록, 표 9개 시점)

- 이 소절과 다음 두 소절은 표 9개 시점(14표 재검토 이전)의 04 문서 3-1~3-3절 복원본. 당시 판단 기록
- 현행: 관측 단위 = 고유 fund_key, 「문서 = 펀드」 자동 성립하지 않음(「저장 단위와 계산 단위」·「기준일과 대표본 선택」)
- 당시 결정: 관측 단위 = 문서(DART 접수번호 1건, 금투협 공고 1건). 클래스 단위로 세지 않음
- 당시 근거
  - 같은 문서가 여러 클래스에 걸친 사례(신한미국나스닥100인덱스증권자투자신탁의 E4671·E4669·E4688)
  - 클래스 단위로 세면 클래스가 많은 펀드일수록 정규화 분포·최소 표본 계산에서 과대 대표
  - fund_key로 클래스를 묶고 최신본 규칙(「판매 중」 스냅숏에서 그 시점의 최신 유효 문서 1건만 계산)을 적용하면 문서 1건 = 펀드 1건
- 당시 남긴 구멍: 간이투자설명서가 금투협과 DART 양쪽에서 옴
  - `source_doc_key` 체계가 소스별로 달라 `lineage_id`로 두 소스의 같은 원고를 잇지 못함
  - 같은 실체가 문서 표에 2행이면 모집단 이중 계수
  - 당시 처리: 1단계에서 규칙을 정하지 않고 2단계 측정 과제로 이관(같은 원고라도 생성 경로가 다르면 sha256이 다를 수 있음)
  - 09-20 이후 측정 방법 변경: DART의 간이투자설명서는 본문 PDF 안의 절 → 파일 해시가 아니라 절 단위 대조([2단계 입력](pipeline-flow.md) 「먼저 측정할 것: 소스 간 중복률」)

### 위험등급 층화 키의 내생성 논증 (09-14~20 기록, 표 9개 시점)

- 제기된 문제: 층화 키의 위험등급은 채점 대상인 투자설명서 자체에서 추출한 값. 채점 대상 문서의 속성으로 그 문서의 점수를 정규화하는 것이 내생성 문제를 만드는가
- 09-20 정정: 금투협 첨부 PDF 본문에도 같은 표기 확인. DART가 유일한 원천 아님([소스별 데이터 현황표](records/phase1-erd/source-profile.md) 「값 표기」)
- 값의 내생성: 없음
  - 위험등급은 정량 9개·정성 6개 기준으로 산정, 산정 주체는 원칙적으로 판매업자
  - 상품의 변동성·구조적 복잡도를 반영하는 값. 문장의 난독성(CDI가 재는 것)을 반영하지 않음
  - 위험등급이 CDI의 함수이거나 그 반대인 순환 관계 없음
- 결측 패턴의 내생성: 우려 남음
  - 파싱이 어려운 문서일수록 위험등급 추출도 함께 실패할 가능성
  - 문서 품질이 CDI 계산 난이도에도 영향을 주면 위험등급 결측과 CDI 계산 난이도가 같은 원인으로 상관
  - 값의 내생성이 아니라 같은 파이프라인·같은 원인에 의한 결측 선택 편향. 특정 성격의 문서가 모집단에서 드러나지 않게 빠짐

| 안 | 내용 | 통계적 함의 |
|---|---|---|
| (a) 유지 | 상품군 × 위험등급 | 09-14 공유 전제가 CDI 정의의 일부로 「동일 위험등급」을 확정. 투자자가 실제로 참고하는 리스크 지표라 목적에 가장 직접 부합. 결측 선택 편향 우려는 남음 |
| (b) 교체 | 상품군 × fndTp/prdClsfCd | fndTp는 공공데이터포털(문서 외부, 등록 정보)에서 나와 결측이 문서 품질과 상관될 구조적 이유 없음 — 더 외생적. 그러나 자산군 분류이지 위험도(1~6단계) 아님 → 「동일 위험등급 비교」라는 CDI 개념 자체가 바뀜. ELS·ETF 전반에 일관되게 채워지는지 미확인 |
| (c) 병행 | 둘 다 상품 표에 확보, 3단계에서 최종 선택 | 결정을 미루면서 잔차 회귀에서 두 변수 중 CDI와의 상관·결측 패턴이 적은 쪽을 데이터로 검증 가능 |

- 당시 권고: (c). 09-16 스키마의 잠정 층화 키는 상품군 × 위험등급 유지, fndTp·prdClsfCd는 문서 외부 통제변수 후보로 상품 표에 확보
- 당시 아키텍트 의견: fndTp·prdClsfCd는 대체가 아니라 보조 층화 축 후보. 권고 (c)와 같은 방향
- 현행(09-23 회의록 조회 기준): 층 = 상품군 × 위험등급만. fndTp/prdClsfCd는 확보만 하고 층에 자동 추가하지 않음
  - fndTp·prdClsfCd 값 형식은 확인대기(9차 미팅). 데이터 엔지니어링·인프라(주영)가 API 조회로 확인
- 판매사·문서 유형·제출연도를 층에 넣지 않은 당시 이유
  - 판매사: 층이 과도하게 쪼개져 표본 부족 위험 증가. 판매사 효과는 잔차 회귀의 설명변수로 통제
  - 문서 유형·제출연도: 층을 나눌 만큼 의미 있는 축인지 미확인. 제출연도는 「판매 중」 판정 시점 규칙으로 흡수
- 09-20 보완 1 — 이름 교정: 「잔차 회귀의 내생성」이 아니라 「층화 정규화의 결측 선택편향」. 층화는 인과 계수 추정이 아니라 동일 등급 내 백분위를 만드는 기술적 정규화
- 09-20 보완 2 — 공통 교란: 위험등급은 표지의 집합투자업자(운용사) 분류이고 CDI도 같은 운용사가 쓴 문서에서 나옴
  - 위험을 보수적으로 매기면서 문서도 신중하게 쓰는 운용사가 있으면 두 값의 공통 원인
  - 결측이 아니라 값 자체의 잠재적 공통 원인. 위 「값의 내생성 없음」 결론에 포함되지 않음
  - 대응: 3단계 잔차 회귀에 운용사 고정효과 투입
- 금투협 PDF에도 위험등급이 있다는 사실의 영향
  - 논증 전제를 성립하지 않게 만들지는 않음. 같은 범주의 문서라 「파싱이 어려운 문서일수록 위험등급도 CDI도 함께 실패」 구조 유지
  - DART 표지 추출 실패 시 금투협으로 대체 획득할 여지는 생김
  - 금투협 PDF에서 위험등급이 몇 % 추출되는지 미측정. 현재는 근거 없는 낙관

### 위험등급 결측과 매칭 편향 (09-14 기록, 표 9개 시점)

- 당시 전제: 위험등급은 DART 한 소스에만 있음(09-20에 금투협 첨부에서도 확인되어 전제 변경)
- 위험등급은 조인을 통해서만 상품에 붙음
  - 조인 실패(「상품 못 찾음」) 시 위험등급이 비어 층 배정 불가 → 모집단에서 사실상 제외
- 편향 방향: 조인 실패가 특정 상품군(ETF)·특정 판매사에 몰리면 그 집단이 과소 표집되어 CDI 분포 자체가 왜곡. 드러나지 않게 빠져 발견이 늦음
- 추적 방법: 매칭 실패를 행 단위로 기록([매칭 규칙](matching-rules.md) 「매칭 실패 기록」)
  - 실패 로그의 상품군·판매사 분포를 모집단 포함 상품 분포와 비교 → CDI가 어느 집단에서 얼마나 과소·과대 표집됐는지 사후 검증
  - 스키마의 책임은 여기까지. 결측 위험등급 대체(imputation) 방법론은 3단계 이후 사안
