# 소스별 데이터 현황표

## 개요

| 항목 | 내용 |
|---|---|
| 티켓 | 「데이터 가져온거 보고 분석해보기」 (정담당 주영 / 부담당 대현, 마감 09-14) |
| 작성 | 대현, 09-20 (제재공시 칸 09-22 보강) |
| 완료 조건 | 완료 체크하지 않음. 조건 3(샘플 머지)·4(싱크 공유)는 주영 몫 |
| 성격 | 「받아보니 무엇이 들어 있나」. 값의 성질만 기록. 그것으로 무엇을 할지는 [데이터 테이블·ERD 설계](../../data-model.md), [원본 보관과 수집·파싱 실패 처리 규칙](../../storage-and-failure-rules.md), [상품·법인 매칭 규칙](../../matching-rules.md) |
| 호출 방법 | [데이터 소스 수집 명세](../../data-sources.md) |

## 결론

| 물음 | 답 |
|---|---|
| 7항목을 4종 모두 채웠는가 | 09-22 제재 표본 8건으로 값 형태 확인. API 과거 커버리지와 누적 전수는 미확정 |
| 가장 큰 발견 | 제재공시 날짜 필터는 `inputDate`(공시 입력일시) 기준이며 `actReqDate`(제재조치일)가 아님. 08-25 조치 건이 09-03 입력되어 09월 조회에 나온 사례로 확인(「기간 분포와 증분 축」) |
| 표 구조를 바꿀 문제 | 2건. 09-20 금투협 실측으로 한 건 소멸. 둘 다 「무엇을 분모로 세는가」 문제(「표 구조를 바꿀 문제 2건」) |
| 09-14에 「모름」이던 판매사 표기 | 해소. 소스 셋이 각각 다르게 줌(「판매사 이름 표기」) |

## 읽는 법

- 전수와 결측률을 같은 표에 놓을 수 있는 것은 문서 단위 4종: DART 펀드공시 · 제재공시 · 분쟁조정결정례 · 금투협 수시공시
- 행 하나가 「공시 문서 1건」이고 발행일·발행 주체·본문·첨부가 공통
- finlife · KRX · 공공데이터포털은 이 표에 넣지 않음. 결측의 뜻이 다름

| | 결측의 뜻 |
|---|---|
| 문서 4종 | 「문서에 첨부가 없다」 |
| API 3종 | 「필드 값이 비어 있다」 |

- 기간 창은 통일하지 않음(09-14 결정). 최근 90일로 자르면 분쟁조정이 사실상 0건이 되는데, 분쟁조정은 검증 라벨 후보라 누적 전체를 봐야 했음

## 필수 칸 결측

- 「수수료」는 결측률 대상에서 뺌(09-14 결정). 어느 API에도 수수료 필드가 없고 투자설명서 본문에서 뽑는 값

| 소스 | 결측 실측 |
|---|---|
| DART 펀드공시 | 표본 10건 기준 — 펀드코드 10/10 있음, 위험등급 10/10 있음, 판매회사 명단 0/10 |
| 제재공시 | 09-22 저장 CSV 재집계(8건). `emOpenNo` 공백 8/8, 구조적 결측 여부는 추가 검증 필요. `-`는 `actOrganCon` 1/8, `actOfficerCon` 1/8, `actEmpCon` 3/8. 원문 값을 보존하고 「해당 조치 없음」과 결측을 구분. 다른 달로 일반화하지 않음 |
| 분쟁조정결정례 | 본문 추출 실패가 결측. 팀 09-05 기록은 첨부 213단위 중 HWP 3.0 94건 · 배포용 7건. 09-20 저장소 실측(최신 글 8개, 첨부 15건)은 15/15 전부 HWP 5.0, 추출 성공. 최신 문서에 치우친 표본이라 전수 비율과 다름 |
| 금투협 수시공시 | 표본 1,499행에서 파싱 대상 13칸 전부 결측 0.00% |

- DART 판매회사 명단 0/10은 누락이 아니라 구조적 부재. 표지에 「각 판매회사 본·지점」 안내 문구만 있음. 판매사는 금투협에서 받음([조인 키 확인 기록](join-key-checks.md) 「판매회사 명단 소스」)

## 값 표기

| 소스 | 실측된 표기 |
|---|---|
| DART 펀드공시 | 위험등급 `2등급[높은 위험]` / `2등급[ 높은 위험 ]` / `2등급[높은 위험 ]`. 표본 10건 안에서 공백 변형 3종. 1~6등급, 1등급이 최고위험 |
| 제재공시 | 09-22 실측(8건). 응답 인코딩 `euc-kr`, `resultCode` 네 갈래. `actReqDate`는 `2026.9.17.`처럼 `YYYY.M.D.`(월·일 앞자리 0 생략, 끝에 점), `inputDate`는 `2026-09-17 13:30:31.0`처럼 `YYYY-MM-DD HH:MM:SS.f`. `finInstName`의 법인격 표기 위치가 회사마다 다름: `㈜비엔케이투자증권`(전치)과 `다올투자증권㈜`(후치)가 같은 표본에 섞임 → 법인명 정규화 3단계가 「위치 무관 제거」를 요구하는 근거 |
| 분쟁조정결정례 | 해당 없음(위험등급·수수료 같은 정형 값이 없는 서술형 문서) |
| 금투협 수시공시 | `standardCd` 접두 3종 `K55` 887 / `KR5` 603 / `KRM` 9. 한 칸에 두 코드 체계 혼재. PDF 본문 위험등급은 `투자 위험등급 N등급[명칭]` |

- 공백 변형은 정규식으로 흡수. `(\d)등급`까지만 보고 뒤를 버리는 것이 안전

## 판매사 이름 표기

소스 셋이 각각 다르게 줌. 합치려면 정규화 필요([상품·법인 매칭 규칙](../../matching-rules.md) 「법인명 정규화」).

| 소스 | 표기 | 예 |
|---|---|---|
| 금투협 판매회사 마스터 | 한글 법인명 + 판매사코드 | 200곳. 코드가 있어 문자열 매칭 불필요 |
| 제재공시 `finInstName` | 법인격 없는 약칭 | `교통은행` |
| 분쟁조정결정문 | 마스킹 | `●●증권` · `○○○○○○ 주식회사` |
| DART 표지 | 없음 | 안내 문구만 |

- 운용사 쪽은 구 상호가 주의할 점. 536건 중 97건(18%)이 구 상호를 갖고, 그중 44건은 업종 접미사까지 바뀜(`누림투자자문` → `누림자산운용`). 유사도로 잡히지 않음([`kofia_mgmt_codes.csv`](../../../research/samples/kofia_mgmt_codes.csv)의 `former_name`)

## 상품명 표기

| 소스 | 표기 |
|---|---|
| DART 펀드공시 | 정식 명칭. `미래에셋밸런스롱숏증권자투자신탁1호(채권혼합)` — 호수를 `1호`로 |
| 금투협 수시공시 | `미래에셋밸런스롱숏증권자투자신탁 1(채권혼합)` — 공백 + `1`. 클래스 행은 `└▶` 접두 |
| KRX (참고) | 상장 약명 `1Q 200액티브` ↔ 정식 `하나1Q200액티브증권상장지수투자신탁[주식]` |
| 분쟁조정결정례 | 마스킹 `▣▣ ▤▤▤▤▤ 아시아 무역금융 전문투자형 사모투자신탁1호` — 고유명만 가림 |
| 제재공시 | 마스킹 `㉮펀드` |

- 펀드명은 조인 키로 부적합 확정. DART와 금투협의 공백·호수 표기가 다르고, KRX는 이름 공간 자체가 달라 완전일치 0.0%([금투협 중복 행·ETF 이름 규칙 검증](kofia-rows-and-etf-rule.md) 「이름 공간 차이」)

## 이상값

| 소스 | 이상값 |
|---|---|
| DART 펀드공시 | 「[ 본 문 ]」 요소가 PDF 링크 한 줄(10/10). 본문이 잘려 온 것이 아니라 원래 구조 |
| 제재공시 | 아래 표 |
| 분쟁조정결정례 | HWP 3.0 94건(1999~2004), 배포용 7건, BMP 내장 4건(스캔본 아님. `PrvText`로 약 1,022자 부분 복구) |
| 금투협 수시공시 | `tmpV1`의 `ZZZZZZ…` 33건은 결측이 아니라 모펀드 행 표시자. 지우면 자연키가 깨짐. `urllib`로 받으면 응답이 잘림(1,499행 → 43행) |

제재공시 이상값 (09-22 실측, 표본 8건):

- 스펙의 마스킹(`甲`·`乙`·`A지점`·`B증권` 등)이 실제로 나옴. 이번 표본에 `甲` 3회·`乙` 2회·`A지점` 4회·`B증권` 2회
- 마스킹 기호 `㉮`는 펀드 전용이 아님. 제재 대상에 보험대리점 2건이 포함되어 `㉮보험`으로도 쓰임. 상품 종류에 맞춰 바뀌는 범용 마스킹 기호
- 본문(`actObjContent`) 인코딩 이상 세 가지
  - 작은따옴표 자리에 유니코드 이름 그대로인 문자열 `u2018`·`u2019`가 35회. 문자가 아니라 글자 그대로 `u2018`이라는 4글자. 작은따옴표를 표현하지 못하는 처리 과정에서 이스케이프 코드가 문자 대신 남은 것으로 보임
  - 줄바꿈 자리에 글자 `n`이 202회(`"…항n(1) …"`). 원문의 개행 이스케이프에서 역슬래시가 빠지고 `n`만 남은 것으로 추정
  - 각주 기호 † 자리에 `u2020`이 4회
- 파서가 그대로 두면 본문에 의미 없는 글자가 섞임. 본문을 사람이 읽거나 재마스킹 검증에 쓰려면 치환 규칙 필요
- `n` 세는 규칙: 본문 4칸(`actObjContent`·`actOrganCon`·`actOfficerCon`·`actEmpCon`)의 소문자 `n`을 전부 셈. 이 표본에는 알파벳 `n`이 들어간 영어 단어가 없어(익명화 표기가 `A팀`·`E팀`처럼 한 글자) 202개 전부가 줄바꿈 자리

## 기간 분포와 증분 축

| 소스 | 데이터 기간 | 증분에 쓸 날짜 칸 |
|---|---|---|
| DART 펀드공시 | 90일 창 실측 | `rcept_dt` |
| 제재공시 | 2000년 이후 누적(게시판). 09-21 실측: 최근 24개월 월별 조회에서 2026-09만 자료 있음(`resultCnt=8`), 그 외 월은 `900`(자료 없음). 표본 하나로는 분포를 말할 수 없음 | `inputDate` (09-22 판정, 아래) |
| 분쟁조정결정례 | 누적 전체. 추출 성공 112건 중 2015년 이후 52건(46.4%) | 게시글 번호 |
| 금투협 수시공시 | 요청당 1년 미만 창. 과거 구간 백필 가능 | `standardDt` |

제재공시 증분 필드 판정 (09-22):

- 표본 8건 중 1건(토스뱅크)의 `actReqDate`=2026.8.25(08월, 조회 구간 09-01~09-30 밖)
- 이 건이 09월 조회에 나왔고 `inputDate`는 2026-09-03(구간 안)
- 조회 구간 안에 든 쪽이 `inputDate`뿐 → 필터는 `inputDate`에 걸림. `actReqDate`는 필터 대상이 아님
- 증분 수집은 `inputDate`를 워터마크로 사용. 근거가 1건이므로 표본 확대 재검증 필요([원본 보관과 수집·파싱 실패 처리 규칙](../../storage-and-failure-rules.md) 「재시도와 워터마크」)

분쟁조정 연도 분포:

- 데이터가 아니라 파서의 한계. HWP 5.0 채택 시점 때문에 최근 문서일수록 추출에 성공함
- 연도별 비교 분석은 HWP 3.0 파서가 생기기 전까지 유보

- 괄호 안은 판매 경로와 보수 체계만 다른 같은 펀드
- 15행 전부 `announceTtl`·`standardDt`·`companyCd`가 같고 `standardCd` 하나만 다름. `standardCd`에 `KR5`와 `K55` 두 체계가 섞인 것도 이 표에서 보임

| 일치 (938) | `1Q 200액티브` | `하나 1Q 200액티브증권상장지수투자신탁[주식]` |
| 매칭 실패 (229) | `ACE 200TR` | — (붙는 펀드명 없음) |
| 오탐 후보 (435) | — | `삼성 KODEX 미국AI메모리TOP2플러스증권상장지수투자신탁[주식]` |

- 매칭 실패 이유: KRX는 `ACE 200TR`이라는 상장 약명을 주는데, ACE는 구 KINDEX라 포털 정식 펀드명과 브랜드가 아예 다름. 문자열로 좁힐 수 없음

### DART 위험등급 — 같은 값이 세 가지로 적힘

표본 10건 안에서 나온 변형([09-14 초기 소스 확인](initial-source-checks.md) 「DART 표지 10건 실측」).

```
2등급[높은 위험]      2등급[ 높은 위험 ]      2등급[높은 위험 ]
```

- 정규식은 `(\d)등급`까지만 보고 뒤를 버려야 안전

### 분쟁조정 — 마스킹 모양

```
【 ○○○ : ●●증권 】
▣▣ ▤▤▤▤▤ 아시아 무역금융 전문투자형 사모투자신탁1호
●●손해보험㈜    ●●카드㈜    ○○○○○○ 주식회사
```

- 회사명은 `●`, 상품명은 `▣`·`▤`로 가려짐. 업종(증권·은행·보험·카드)만 남음

### 제재공시 — 본문 마스킹과 인코딩 이상

금감원 공개 샘플의 `actObjContent`. 상품·사람·지점·거래처가 전부 기호.

```
잘못 매수한 ㉮펀드(가입액 10백만원)를 환매하고 … 乙 본인 자금으로 ㉮펀드를 매수하여
甲에게 … A지점은 2007.11.1. … ㈜C(대표 戊) 등 15개 업체에 대하여
```

- 금융회사명은 실명. 샘플 값 `교통은행`, 법인격 표기가 없는 약칭

09-22 실측(2026-09 조치 8건). 위 마스킹 패턴을 실제 데이터에서도 확인. 8건 중 2건이 보험대리점 제재라 `㉮`가 범용 상품 마스킹 기호임이 드러남.

```
잘못 매수한 ㉮펀드를 환매하고 甲에게 … A지점은 2007.11.1. … B증권 등 위법한 거래*를 감추어 주기 위해,
* u2018제3자 이익도모 금지 회피 목적의 투자일임·신탁재산 간 연계거래u2019 등으로
```

- 두 번째 줄이 인코딩 이상. 작은따옴표 두 개가 문자가 아니라 `u2018`·`u2019`라는 4글자 문자열 그대로 들어 있음
- 줄바꿈 자리에도 `n`이라는 글자 하나가 그대로 섞임(`"…항n(1) …"`)
- 본문을 사람이 읽거나 마스킹 검증에 쓰려면 이 패턴들을 먼저 치환해야 함

표본 8건의 실측 횟수 (본문 4칸 기준).

| 들어 있는 글자 | 원래 문자 | 횟수 |
|---|---|---|
| `u2018` + `u2019` | 작은따옴표 | 35 |
| `u2027` | 가운뎃점 | 3 |
| `u2020` | † (각주) | 4 |
| `u203B` | ※ | 1 |
| `n` | 줄바꿈 | 202 |

- `n` 202회 정정 이력은 「정정 이력」

### 운용사 구 상호 — 유사도로 못 잡는 이유

[`kofia_mgmt_codes.csv`](../../../research/samples/kofia_mgmt_codes.csv) 원본 536건 중 97건(18%)이 구 상호를 가짐.

```
누림투자자문  →  누림자산운용        (업종 접미사까지 바뀜)
아주자산운용(주) / 파란자산운용 / 아이스텀자산운용 / 도이치자산운용
```

- 「투자자문」과 「자산운용」은 문자열 유사도로 이어지지 않음. 치환 사전이 필요하며 그 사전이 `former_name` 열

## 표 구조를 바꿀 문제 2건

- 티켓 완료 조건 2번이 요구한 「3건 이하」
- 둘 다 「무엇을 분모로 세는가」 문제
- 초판은 3건. 「「전수」 칸이 모든 소스에 성립하지 않는다」가 문제 1이었으나, 근거였던 「금투협은 조회 창이 1년이라 누적 전수가 없다」가 09-20 실측으로 성립하지 않게 되어 소멸(「전수」)

### 문제 1: 분쟁조정은 분모가 셋

- 사건 814건 / 금융투자 187건 / 첨부 845개가 모두 다른 분모
- 「추출 성공 112건」은 첨부 213단위 기준이며 사건 187건이 아님
- 결측률 칸에 분모를 함께 적는 칸이 없으면 이 숫자들은 반드시 섞임

### 문제 2: 「결측」이 두 가지 뜻

- 문서 4종에서는 「첨부가 없다」, API 3종에서는 「필드가 비었다」
- 원본파일 표와 상품 표가 각각 다른 뜻의 결측을 담는데 칼럼 이름이 같음
- 실패 상태값처럼 원인을 구분하는 값이 결측에도 필요

- 두 문제의 결정 대기 위치: [원본 보관과 수집·파싱 실패 처리 규칙](../../storage-and-failure-rules.md) 「미결」

## 제재 API 과거 조회와 미확정 커버리지

- 기존 조회 기록에는 2026-01~08을 조회해 정상 0건(`900`)을 받았다고 적혀 있음
- 28일×9구간이라는 요약만으로 실제 요청 시작·종료일과 누락 없는 범위를 입증할 수 없음. 전체 커버리지는 요청 로그 대조 후 확정

| 조회 구간 | 결과 |
|---|---|
| 2026-01~08 조회 기록 | 0건 보고. 정확한 요청 구간·누락 여부 재검증 필요 |
| 2026-09-01 ~ 2026-09-30 | 8건 |
| 최근 24개월 월별 (09-21 실측) | 2026-09만 자료 있음, 나머지 전부 `900` |

- 게시판 경로는 2000년 이후 5,735건. 저장된 API 표본은 8건이며 게시판과의 범위·키 대응은 미확정
- 09-21 기록은 해당 호출에서의 관찰이며 API의 영구 보존 정책이나 더 오래된 자료의 부재를 입증하지 않음
- 원인 미확인. API가 최근 입력분만 노출하는 구조로 보이나 금감원 문서에 설명이 없고, 더 확인하려면 조회 한도를 더 써야 함. 추정이며 사실 아님
- 막는 일: 민석 「판매사별 라벨 표 — 제재공시 기반」(10-07)은 판매사마다 제재 이력을 세는 작업. API만 쓰면 재료가 8건뿐이라 표가 성립하지 않음. 게시판 경로(5,735건)를 쓰거나 API 노출 범위를 금감원에 확인하는 것 중 하나가 10-07 전에 필요([3단계 입출력 Schema 설계 입력](../../io-schema.md) 「미결」)

| 사유 | 뜻 | 실패율에 넣나 | 이번 표본 |
|---|---|---|---|

- 표본이 늘었을 때 은행·증권사가 이 사유로 반복되면 마스터 자체가 오래된 것인지 다시 봐야 함. 지금은 1건뿐이라 판단 불가
- 현행 규칙: [상품·법인 매칭 규칙](../../matching-rules.md) 「제재공시 법인 매칭」
