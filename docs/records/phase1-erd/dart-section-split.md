## 측정 이유

저장소 안의 근거 셋이 서로 충돌한 채 남아 있었고 시도 기록이 한 건도 없었음.

| 문서 | 주장 |
|---|---|
| 당시 데이터 소스 API 명세(현 [데이터 소스 수집 명세](../../data-sources.md)) | 「DART가 절(`eleId`) 단위로 주는 것은 표지와 변경요약뿐이고 **본문은 PDF 파일 하나**다」 |
| `05-timeline.md` (PM) | 「DART 정형 HTML. **파싱 난도 하향**, 「파싱이 최대 난도」라는 전제 무효」 |
| `09-plan-review/02-data-engineer.md` | 「목차 태그 `h2`/`h3` 기준 분할… **규칙 기반으로 충분**」 |

이 판정에 걸린 것:

- 「원문 절 단위 분할과 소스별 실패율 산출」(10-01~10-14, 여유 0일)
- 파이프라인 가동 점검 「문서 500건 이상 텍스트화」
- 절 표와 점수 표 전체
- 최종 산출물 목표 1단계인 부·절별 채점

## 결론

| 물음 | 답 |
|---|---|
| 본문 PDF에 텍스트 층이 있는가 | 있음. 스캔본이 아님 |
| PDF에 북마크(목차)가 있는가 | 없음. `/Outlines` 0건 |
| 부 단위로 나눌 수 있는가 | 가능. 9건 부 45/45 (첫 5건 25/25) |
| 절 단위로 나눌 수 있는가 | 가능. 292/294 = 99.3% (첫 5건 161/163 = 98.8%) |
| 모든 문서에 통하는가 | 아님. 10건 중 1건(`20260914000126`)은 「제N부」 표제를 찾지 못해 실패 |
| 외부 의존성 | `pdftotext`(poppler) 하나. 인증키 불필요 |

- 「본문이 PDF 파일 하나」는 맞음. 그것이 절 분할을 막지는 않음
- 세 주장 중 데이터 소스 명세가 사실을 정확히 적음. 다른 둘은 결론(난도 하향 / 규칙 기반으로 충분)만 맞았고, 근거로 든 「정형 HTML」과 「`h2`/`h3` 태그」는 둘 다 존재하지 않음

### 실패 1건

- `20260914000126`: 「제N부」 표제를 찾지 못함
- 부 체계를 쓰지 않는 문서로 보이나 원인은 확인하지 않음
- 10건 중 1건이므로 이런 문서가 얼마나 되는지는 표본을 더 넓혀야 앎. 이 방법이 통하지 않는 문서 유형이 있다는 신호

## 방법

1. `dsaf001/main.do?rcpNo=`에서 문서 트리를 읽어 「[ 본 문 ]」 노드를 찾음
2. `viewer.do`로 그 노드를 받으면 PDF 링크 한 줄
3. `download.do`로 PDF 수신 (`application/pdf`, 표본은 0.7MB / 65쪽)
4. `pdftotext -layout`으로 텍스트 추출
5. 문서 앞의 목차에서 부별 절 제목을 읽고, 본문에서 그 제목을 찾아 경계로 사용

- 호출 형식: [데이터 소스 수집 명세](../../data-sources.md) 「DART」

## 주의할 점

실측에서 전부 실제로 걸린 것.

| # | 주의할 점 | 대응 |
|---|---|---|
| 1 | 트리 JS가 `var node1 = {}`을 노드마다 재사용. 변수명으로 정규식을 걸면 마지막 노드 하나만 잡힘. 처음에 「노드가 1개」라는 결과를 얻음 | 블록 단위로 끊어 읽음 |
| 2 | 들여쓰기로 목차와 본문을 가를 수 없음. 첫 구현(「목차는 1열, 본문 표제는 들여쓰기」)은 5건 중 3건만 처리 | 제1~5부가 오름차순으로 한 번 나오면 목차, 다시 나오면 본문. 오름차순 묶음으로 끊어 5건 전부 5/5 |
| 3 | 목차의 마지막 부 다음에 「투자자 유의사항」이나 「요약 정보(간이투자설명서)」가 붙고 거기에도 `1.` `2.`가 있음. 그대로 읽으면 제5부 절이 6개에서 24개로 실제보다 크게 나옴 | 절 번호는 부 안에서 단조 증가. 번호가 되돌아가면 목차가 끝난 것으로 봄 |
| 4 | `file` 명령이 표본 PDF를 「10 pages」로 표시. 실제는 65쪽 | `file`의 쪽수를 쓰지 않음 |

들여쓰기 실측 (주의할 점 2):

| 문서 | 목차 들여쓰기 | 본문 표제 들여쓰기 |
|---|---|---|
| 20260911000067 | 0칸 | 2칸 이상 |
| 20260911000035 | 0칸 | 15~25칸, `제1부.`처럼 마침표가 붙음 |
| 20260911000231 | 4칸 | 2~6칸 |

## 찾지 못한 절 2건

- 원본 문서 `20260911000035`에서 절 2개를 찾지 못함
- 목차 제목과 본문 표제의 표기가 다른 것으로 보이나 확인하지 않음
- 표본을 9건으로 넓혀도 못 찾는 절은 이 2건뿐(292/294)
- 수동 확인 큐로 보내면 됨. 못 찾은 절은 그 부의 나머지 구간에 포함되므로 텍스트를 잃지 않음
